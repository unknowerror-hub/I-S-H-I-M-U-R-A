# SYSTEM ISHIMURA // CORE SEC-INTELLIGENCE PROTOCOL

Комплексная нейросетевая система информационной безопасности, сканирования уязвимостей, контроля целостности инфраструктуры и автоматического реагирования на инциденты. Предназначена для непрерывного аудита серверов под управлением Linux, Docker-контейнеров, сетевых периметров и защиты кодовой базы ядра.

---

## 🛠 АРХИТЕКТУРА И ИНФРАСТРУКТУРА СИСТЕМЫ

* **Операционная система**: Linux Ubuntu/Debian Core.
* **Веб-окружение**: Apache HTTP Server (`www-data:www-data`), обслуживающий интерактивную панель управления.
* **База данных**: СУБД PostgreSQL (`ishimura_admin` / база: `ishimura`).
* **Корневые директории проекта**:
  * `/opt/ishimura/` — исполняемые ИИ-модули, демоны, локальные конфигурации и теневые слепки.
  * `/opt/ishimura/web/` (`/var/www/html/`) — фронтенд-интерфейсы, панели управления модулями, глобальные JS-ядра.

## 📡 СПЕЦИФИКАЦИЯ И ОБНОВЛЕНИЯ МОДУЛЕЙ

### 1. 🛡️ MIFIKO (Integrity Monitor & Auto-Recovery Core) — **ОБНОВЛЕН**
* **Назначение**: Нейросетевой контур слежения за системой в реальном времени с контролем повышения прав учетных записей, анализом состояния файлов ОС и Docker-контейнеров.
* **Реализованный функционал**:
  * **Автогенерация БД**: При установке и первичном развертывании модуль автоматически генерирует схему таблиц в PostgreSQL (`mifiko_integrity`, `mifiko_docker_status`, `ishimura_extensions`), исходя из описания своих ИИ-функций.
  * **Синхронизация с Ashka**: Каждые 5 минут проводит автоматическое сканирование рабочих директорий системы и сравнивает хэш-суммы файлов (`SHA-256`) с эталонной теневой копией, созданной модулем Ashka.
  * **Умная группировка советов**: Встроен алгоритм дедупликации аномалий. Повторяющиеся предупреждения безопасности (например, беспарольный доступ `www-data` к утилитам через `/etc/sudoers` или избыточное выделение RAM контейнерам) автоматически агрегируются в уникальные карточки рекомендаций ИИ.
  * **Двухвекторное управление инцидентами**:
    * **[ПОДТВЕРДИТЬ ВАРИАНТ ВСЕ ОК]**: Позволяет легитимизировать текущие модификации, если изменения кодовой базы вносились администратором. Критический баннер скрывается, новые хэши принимаются за эталон.
    * **[ПЕРЕЗАПИСАТЬ ИЗ РЕЗЕРВНОЙ КОПИИ]**: Запускает автоматическую процедуру горячей реанимации кодовой базы и перезаписи файлов оригинальными слепками из защищенных `.tar.gz` архивов Ashka.
  * **Интерактивные фиксы**: Реализована функциональная кнопка «Применить» напротив каждой рекомендации ИИ. При нажатии утилита выполняет оптимизацию (например, ограничение памяти контейнера до 2GB с флагом `--memory=2g`), подсвечивает строку зеленым статусом безопасности и блокирует повторные клики.
  * **Управление интерфейсом**: Добавлены кнопки мгновенного скрытия рекомендаций и полной очистки интерактивного терминала событий.

### 2. 🗄️ ASHKA (Backup Daemon & Shadow Storage Control)
* **Назначение**: Модуль управления резервным копированием, автоматического создания моментальных снимков (снапшотов) системы, БД и поддержания директории `.shadow_storage`.
* **Функции**: Генерирует архивы вида `ishimura_snapshot_*.tar.gz`, выступающие физическим эталоном целостности для верификаторов Mifiko.

### 3. 🕷️ ARACHNA (Network Scanner Engine) — **ИСПРАВЛЕН**
* **Назначение**: Движок сканирования сетевых портов и детектирования уязвимостей внешних/внутренних хостов инфраструктуры.
* **Исправления**: Устранена критическая ошибка `AttributeError: module 'socket' has no attribute 'AF_DGRAM'` в файле `arachna_engine.py`, вызванная конфликтом локальных импортов. Восстановлена авторизация демона в PostgreSQL для бесперебойного ведения таблиц сканирования `vulnerability_scans`.

### 4. ⚔️ LAMIA (eBPF Shield & Traffic Filter)
* **Назначение**: Низкоуровневый защитный экран ядра Linux на базе eBPF-сессий.
* **Функции**: Выступает в роли исполнительного механизма по рекомендациям ИИ Mifiko — перехватывает сессии, ограничивает права скомпрометированных пользователей (например, `www-data`) и фильтрует сетевые аномалии на лету.

### 5. 🔌 МОДУЛЬНОЕ РАСШИРЕНИЕ СИСТЕМЫ (Plugin Architecture)
Согласно ТЗ, архитектура Ishimura поддерживает динамическое расширение возможностей системы без остановки ядра.
* Новые модули могут быть загружены горячим способом через веб-панель настроек.
* Структура нового расширения строго регламентирована и должна состоять из двух связанных компонентов:
  1. Скрипт бизнес-логики на языке Python (`.py`), помещаемый в `/opt/ishimura/modules/<name>/`.
  2. Веб-интерфейс управления модулем на PHP/HTML, интегрируемый в `/opt/ishimura/web/modules/<name>.php`.

## 🕒 СИНХРОНИЗАЦИЯ СИСТЕМНОГО ВРЕМЕНИ (Глобальное исправление)

Для устранения рассинхронизации между метками создания бэкапов Ashka и записями в системный журнал событий на фронтенде, во всей инфраструктуре развернута единая временная зона **Europe/Moscow (UTC+3)**:
* Системное время Linux переведено на московский эталон через `timedatectl`.
* Файлы конфигурации `php.ini` веб-сервера принудительно зафиксированы директивой `date.timezone = "Europe/Moscow"`.
* Глобальное JS-ядро системы (`/opt/ishimura/web/js/core.js`) оснащено централизованным методом `getIshimuraLocalTime()`. Все асинхронные логи веб-панелей теперь рассчитывают смещение часового пояса на стороне клиента и выводят таймстампы секунда в секунду с системным временем демонов.
